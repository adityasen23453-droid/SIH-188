2. Executive Summary & Problem Definition

2.1 Background & Operating Context

The Sashastra Seema Bal (SSB) oversees border security across India's open, visa-free borders with Nepal (1,751 km) and Bhutan (699 km). Border outposts and Integrated Check Posts (ICPs) handle high pedestrian and vehicular traffic daily. Travelers present a heterogeneous mix of documents: Indian and Nepalese/Bhutanese citizens carry domestic identity cards (Voter ID/EPIC, Aadhaar, Driving Licenses, Transit Permits), while third-country foreigners carry international Passports and Visas.

2.2 Problem Statement & Core Operational Vulnerabilities

Current border verification relies on visual human inspection and isolated database lookups. This operational model suffers from critical vulnerabilities:

  • High Passenger Bottlenecks: Manual checks take 2–5 minutes per person, leading to severe congestion.
  • Undetected Physical & Digital Tampering: High-quality color photo replacements, edited dates of birth, and counterfeit visa ink stamps cannot be caught by visual inspection alone.
  • Identity Impersonation: Lookalike individuals travel on genuine documents of other persons.
  • Multiple Identities by the Same Person: Trans-border criminals and smugglers create multiple identity cards across different jurisdictions under different names.
  • Lack of an Immutable Audit Trail: Border logs on traditional spreadsheets or isolated servers are vulnerable to unauthorized modification or repudiation.

2.3 Solution Vision

Develop Project Guardian, an integrated, AI-driven, and blockchain-audited border screening platform that captures document images and live face feeds, executes automated perspective correction, extracts dual-zone OCR data, validates standard checksums (ICAO 9303, Aadhaar Verhoeff), detects multi-signal digital forgeries (ELA + ViT + EXIF), verifies biometrics (1:1 match and 1:N FAISS duplicate search), and outputs an explainable risk score (0–100) with immutable ledger commit within under 2.5 seconds.

6. Detailed Functional Requirements (FR-01 to FR-08)

FR-01 Automated Document Ingestion & Computer Vision Preprocessing Core CV

Description: The system must accept camera/scanner uploads (JPEG, PNG, WEBP), identify quadrilateral document borders, and deskew the image to a standardized top-down orientation.

  • FR-01.1: Automatically rescale high-resolution images to target height (1000px) and apply Gaussian blur with Canny edge detection.
  • FR-01.2: Locate the largest convex contour using cv2.approxPolyDP and compute a 4-point perspective transform (cv2.warpPerspective).
  • FR-01.3: Apply Contrast Limited Adaptive Histogram Equalization (CLAHE) on the LAB L-channel to eliminate glare and shadows.
FR-02 Dual-Zone Optical Character Recognition (OCR) Engine Core OCR

Description: The system must extract text across both structured Machine Readable Zones (MRZ) and unstructured Visual Inspection Zones (VIZ).

  • FR-02.1: Parse 2-line TD3 MRZs via PassportEye and extract Name, Passport Number, Nationality, DOB, Expiry, Gender, and Check Digits.
  • FR-02.2: Apply scoped positional letter-to-digit auto-correction strictly to numeric positions (DOB: 13-19, Expiry: 21-27, Check digits: 9, 19, 27, 43): O/D→0, I/L→1, Z→2, A→4, S→5, B→8.
  • FR-02.3: Fall back to PaddleOCR / Tesseract for VIZ text extraction and regex pattern matching on Voter IDs and Driving Licenses.
  • FR-02.4: Flag character-level extraction plausibility with confidence ratings (High / Low).
FR-03 Deterministic Standards & Rule-Based Validation Engine Rule Engine

Description: Verify that extracted document data complies with international and national mathematical validation standards.

  • FR-03.1: Compute ICAO Doc 9303 7-3-1 modulo 10 checksums on Passport Number, Date of Birth, Date of Expiry, and Composite Line 2.
  • FR-03.2: Implement the Aadhaar Verhoeff algorithm over the dihedral group D5 to validate 12-digit Indian national identity numbers.
  • FR-03.3: Execute VIZ-to-MRZ Cross-Field Consistency Checks: Compare printed visual name and dates against MRZ decoded values.
  • FR-03.4: Validate date plausibility: Expiration date > Current date; Date of Birth not in future and < 120 years ago; Issue date < Expiration date.
FR-04 Multi-Signal Digital Forgery & Tampering Detection Engine Core AI Innovation

Description: Detect pixel alterations, photo swaps, digital modifications, and re-compression anomalies across four distinct attack vectors.

  • FR-04.1 (ELA Analysis): Re-save input at JPEG Quality 90, compute absolute pixel variance, amplify contrast, save a PNG difference heatmap, and return a normalized 0–100 ELA score.
  • FR-04.2 (AI ViT Classifier): Blend the original image with ELA (alpha=0.3) and execute classification using pretrained Vision Transformer zodumair/document-forgery-detector to output a deepfake/forgery probability.
  • FR-04.3 (EXIF Forensics): Parse EXIF tags for graphic editing tools (Photoshop, GIMP, Canva, Snapseed) and flag stripped/missing metadata.
  • FR-04.4 (Stamp & Seal Forensics): Detect overland immigration stamps and evaluate color histogram consistency and contour edge discontinuities.
FR-05 Biometric Face Verification (1:1 Matching) Biometrics

Description: Verify that the individual standing at the checkpoint matches the photographic portrait printed on the document.

  • FR-05.1: Automatically crop the document portrait photo using facial boundary coordinates or OpenCV cascade detection.
  • FR-05.2: Capture live webcam video frames from the browser via HTML5 MediaDevices.getUserMedia.
  • FR-05.3: Compute 512-dimensional facial embeddings using deep ArcFace / MobileFaceNet networks and evaluate cosine similarity.
  • FR-05.4: Apply calibrated operational decision thresholds: ≥ 0.65 (Verified Match), 0.50–0.64 (Uncertain / Manual Check), < 0.50 (Mismatch / Impersonation Alert).
FR-06 Biometric Duplicate Identity Detection (1:N FAISS Vector Search) Anti-Alias AI

Description: Detect trans-border individuals attempting to cross under multiple identities, aliases, or forged names.

  • FR-06.1: Maintain an in-memory FAISS (Facebook AI Similarity Search) index storing embeddings of previously screened travelers.
  • FR-06.2: On each live face capture, perform an inner-product nearest-neighbor search against the index within ≤ 50ms.
  • FR-06.3: If a matching biometric face (> 0.70 similarity) is discovered under a different name, nationality, or passport number, immediately trigger a "CRITICAL: Duplicate Identity / Alias Detected" alert.
FR-07 Explainable Evidence Fusion & Risk-Scoring Engine XAI Decision

Description: Consolidate multi-modal signals into an auditable 0–100 risk score accompanied by transparent reason codes.

  • FR-07.1: Apply dynamic penalty weights: Blacklist (+50), Biometric Mismatch (+30), Checksum Failure (+25), Document Expired (+20), EXIF Edit Tool (+15), VIZ-MRZ Mismatch (+15).
  • FR-07.2: Categorize decision into 3 triage bands: LOW (< 30): Auto-Admit; MEDIUM (30–60): Secondary Inspection; HIGH (> 60): Immediate Detention.
  • FR-07.3: Output an array of plain-English diagnostic reason codes for immediate officer understanding.
FR-08 Blockchain & Cryptographic Audit Trail Layer Blockchain & Security

Description: Ensure non-repudiation and immutable logging of every border screening event in compliance with the SIH theme.

  • FR-08.1 (Zero-PII On-Chain): Store document images and raw biometrics off-chain. Commit only SHA-256 document hashes, risk scores, model versions, and officer badge IDs.
  • FR-08.2 (Cryptographic Block Hash): Link each event into an append-only hash chain: Block_Hash = SHA-256(Index + Timestamp + Prev_Hash + Doc_Hash + RiskScore + OfficerID).
  • FR-08.3 (Ledger Integrity API): Expose GET /api/ledger/verify to validate that the cryptographic hash chain is uncorrupted and unbroken.

8. Technical Architecture & Database Schemas

8.1 Complete Database Schema (SQLite Off-Chain Store)

-- 1. Document Registry Table
CREATE TABLE IF NOT EXISTS documents (
    document_id TEXT PRIMARY KEY,
    document_number_hash TEXT NOT NULL,
    issuing_country TEXT NOT NULL,
    document_type TEXT NOT NULL,
    issue_date TEXT,
    expiry_date TEXT,
    status TEXT NOT NULL CHECK(status IN ('VALID', 'EXPIRED', 'REVOKED', 'STOLEN')),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 2. Stolen & Blacklisted Documents (Interpol / MHA Watchlist)
CREATE TABLE IF NOT EXISTS blacklist (
    passport_number TEXT PRIMARY KEY,
    reason TEXT NOT NULL,
    flagged_by TEXT DEFAULT 'Interpol SLTD',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 3. Cryptographic Screening Audit Ledger (Immutable Hash Chain)
CREATE TABLE IF NOT EXISTS screening_audit_ledger (
    block_index INTEGER PRIMARY KEY AUTOINCREMENT,
    timestamp TEXT NOT NULL,
    previous_hash TEXT NOT NULL,
    document_hash TEXT NOT NULL,
    risk_score REAL NOT NULL,
    risk_level TEXT NOT NULL,
    reasons_json TEXT NOT NULL,
    officer_id TEXT NOT NULL,
    model_versions TEXT NOT NULL,
    block_hash TEXT NOT NULL
);

10. Risk Management & Contingency Matrix

Identified Risk Severity Impact Description Engineered Contingency / Mitigation
Webcam Unavailable Medium Evaluation laptop or booth has no functioning camera. Pre-packaged test images allow simulated traveler face injection with 1-click fallback.
ViT Inference Delay Medium GPU unavailable on local evaluation machine (CPU fallback > 3s). Model execution runs asynchronously; ELA and metadata scores provide immediate partial preview.
Passport MRZ Creased Low Folds or scratches cause character misreads. Scoped positional letter-to-digit auto-corrector recovers OCR errors; generic OCR acts as fallback.
Database Unreachable Low External internet severed at remote border outpost. Autonomous local SQLite registry stores all blacklist and revocation records on the edge.
